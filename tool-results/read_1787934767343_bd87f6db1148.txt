     9→## A. Top 15 Patterns the Top-100 Starred Repos Share (ranked by frequency in sample)
    10→
    11→Surveyed = 100 top-starred repos as of 2026-08-28. Frequency = % of repos showing the pattern.
    12→
    13→1. **One-word lowercase repo name** (76/100). `openclaw`, `superpowers`, `firecrawl`, `ponytail`, `langchain`, `ollama`, `transformers`, `langflow`, `dify`, `flutter`, `bootstrap`, `excalidraw`, `rustdesk`, `next.js`, `electron`, `godot`, `immich`, `kubernetes`, `vscode`, `tensorflow`, `rust`, `go`, `node`, `d3`, `vue`, `react`. The few that aren't (e.g. `free-programming-books`, `awesome-selfhosted`, `Microsoft-Activation-Scripts`, `system-design-primer`) are content-list repos where the name describes the content type, not a product. **Zero repos in the top-100 use snake_case for the repo name.**
    14→
    15→2. **Centered `<div align="center">` or `<p align="center">` hero block at the very top of README** (88/100). Wraps a `<picture>` with `prefers-color-scheme dark/light` sources, then the `<h1>` title, then an `<h3>` or italic tagline, then a badge row. This is the universal masthead.
    16→
    17→3. **`<picture>` element with `prefers-color-scheme` for dark/light hero art** (61/100 — every repo that ships art at all). Concrete example (uv):
    18→   ```html
    19→   <picture align="center">
    20→     <source media="(prefers-color-scheme: dark)" srcset="…dark.png">
    21→     <source media="(prefers-color-scheme: light)" srcset="…light.png">
    22→     <img alt="…" src="…light.png">
    23→   </picture>
    24→   ```
    25→
    26→4. **Italic one-line tagline directly under the title, before badges** (74/100). Length ≤ 90 chars. Pattern: noun-phrase or verb-phrase that states what the thing IS, never what it does (Houdini = noun, not feature list).
    27→
    28→5. **shields.io badge row, 3-5 badges, style `flat-square` or `for-the-badge`** (95/100). Modern palette: `CI status` → `Latest Release / PyPI version / npm version` → `License` → `Discord` → (optional) `GitHub stars`. The 2018 palette (Travis, Coveralls, Codacy, Gemnasium, David-dm, BitHound) is gone.
    29→
    30→6. **Install command in the first 100 lines, as the first code block** (84/100). Either `pip install x`, `curl -LsSf …install.sh | sh`, `npx x`, `brew install x`, or `claude plugins install x`. Never more than one install path shown before the fold — alternates go in `<details>`.
    31→
    32→7. **Single-word CLI binary name matching the repo name** (88/100 of CLI tools). `uv`, `rg`, `bun`, `deno`, `ollama`, `firecrawl`, `langflow`, `langchain`, `dify`, `ponytail`, `specify` (github/spec-kit's CLI — note: repo is `spec-kit` but binary is `specify`, both single tokens). Subcommand-driven: `uv sync`, `rg --help`, `ponytail …`, `specify init`.
    33→
    34→8. **Quickstart with runnable code in the first 200 lines** (79/100). Three blocks of 5-10 lines max: install → minimal use → output. The "Hello World" of the repo.
    35→
    36→9. **"Table of Contents" H2 right after the hero** (62/100, sharply up from 2024 when it was ~30%). Driven by GitHub's auto-anchor feature and the rise of long READMEs in skills/agent repos.
    37→
    38→10. **`## Installation`, `## Usage`, `## Contributing`, `## License` as the four canonical bottom-of-README sections** (94/100). Order varies only by whether Features comes before or after Installation.
    39→
    40→11. **`## License` is the last H2 of the README and references a LICENSE file in repo root** (97/100). License choices in the top-100: MIT 38, Apache-2.0 22, AGPL-3.0 9, GPL-3.0 7, BSD-3-Clause 6, custom/Other 16, "All Rights Reserved"-ish 2. **MIT dominates for tools/SDKs**, **AGPL-3.0 dominates for "we are the cloud incumbent"-defensive SaaS projects** (Mastodon, Plausible, InvenTree, Cal.com-adjacent).
    41→
    42→12. **Multi-language README mirrors linked from the hero block** (47/100, sharply up from ~15 in 2024). Most common: `简体中文 (zh-CN)`, `Português (Brasil)`, `日本語`, `한국어`, `Español`, `Русский`, `Tiếng Việt`, `ไทย`, `Deutsch`. ECC ships 12 language READMEs; spec-kit, hermes-agent, ponytail each ship 3-6.
    43→
    44→13. **Sponsor / enterprise tier surfaced in the README hero block, not buried at the bottom** (54/100). Patterns: "Commercial Services" section (superpowers, with sales@primeradiant.com), "Sponsor" GitHub Sponsors button (ECC), "Pricing" link (spec-kit, "Private repos from $19/seat/mo"), "Built by $ORG" badge (hermes-agent: "Built by Nous Research").
    45→
    46→14. **Benchmark or numbers block in the first 300 lines, not buried in a /docs page** (29/100 — and ALL of the top 30 fastest-growing 2026 repos do this). uv ships a benchmark `<picture>` and the claim "10-100x faster than `pip`". Mem0 ships a before/after table at the top. Ponytail ships "~54% less code · ~20% cheaper · ~27% faster · 100% safe" with a methodology footnote. **Top-growth repos lead with a number. Content-list repos (#1-#5 in stars) don't, because they have no benchmark to show.**
    47→
    48→15. **Discord community link in the hero badge row** (71/100). Most use `https://discord.gg/...` with a shields.io Discord badge (`color=5865F2`). A growing minority (~12/100) replace Discord with self-hosted Gitter/Zulip/Discourse, but Discord still dominates for new projects in 2026.

    83→### B2. AGENTS.md is the new (de-facto) standard for "instructions for autonomous coding agents"
    84→
    85→- **AGENTS.md** is the cross-tool standard (https://agents.md). Adopted by **60k+ open-source projects** as of 2026-08.
    86→- Supported by 20+ coding agents: **Codex (OpenAI), Jules (Google), Cursor, Factory, Aider, goose, opencode, Zed, Warp, VS Code, Devin, Junie (JetBrains), Amp, RooCode, Gemini CLI, Kilo Code, Phoenix, Semgrep, GitHub Copilot, Ona, Windsurf (Cognition), Autopilot & Coded Agents (UiPath), Augment Code**.
    87→- Emerged from collaboration across **OpenAI Codex, Amp, Jules (Google), Cursor, Factory**.
    88→- **OpenAI's main repo has 88 nested AGENTS.md files** (one per package in the monorepo; agents read the nearest one).
    89→- Canonical AGENTS.md sections: `## Project overview`, `## Build and test commands`, `## Code style guidelines`, `## Testing instructions`, `## Security considerations`. Optional: `## Dev environment tips`, `## PR instructions`.
    90→- **CLAUDE.md is the Anthropic-specific variant** (anthropics/claude-code), now treated as an alias or sibling.
    91→- **Important counter-trend (Feb 2026 arXiv study)**: poorly-written AGENTS.md files **reduce** coding-agent success rates by ~20% and increase token cost. The winning repos write **terse, command-and-concrete-rule files** (uv, codex, langchain, superpowers). The losing repos write vague philosophical files. Lesson: AGENTS.md is a contract, not a mission statement.

    93→### B3. SKILL.md + agentskills.io + skills.sh — the new package manager for "skills"
    94→
    95→- Anthropic published the **Agent Skills spec** (https://agentskills.io). A skill = a folder with a `SKILL.md` file containing YAML frontmatter (`name:`, `description:`) + markdown instructions + optional scripts.
    96→- **`anthropics/skills`** (172k stars) is the canonical reference repo. Badge pattern: `![skills.sh](https://skills.sh/b/anthropics/skills)`.
    97→- **skills.sh** is the cross-tool skills installer: `npx skills@latest add mattpocock/skills` copies editable skill files into your project. Works across Codex, Cursor, etc.
    98→- Claude Code's plugin marketplace pattern: `/plugin marketplace add anthropics/skills` then `/plugin install document-skills@anthropic-agent-skills`.

   100→### B4. Spec-Driven Development (SDD) is a 2026 trend with its own vocabulary
   101→
   102→- `github/spec-kit` (131k stars) defines a 6-step workflow: **0. Establish** (`/speckit-constitution`), **1. Specify** (`/speckit-specify`), **2. Plan** (`/speckit-plan`), **3. Break down** (`/speckit-tasks`), **4. Implement** (`/speckit-implement`), **5. Converge** (`/speckit-converge`). Repeat 4-5 until Converge reports "Converged".
   103→- Single-word CLI: `specify` (`uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z`).
   104→- 1.0.0 shipped Aug 2026 (~1 year after first commit). Anniversary framing was used in the README: "it is now just a number. As agents make adapting to change dramatically cheaper, the value moves from stability to adaptability."
   105→- SDD is now an explicit competitor to GSD, BMAD, and Spec-Kit (per mattpocock/skills README: "Approaches like GSD, BMAD, and Spec-Kit try to help by owning the process. But while doing so, they take away your control").

   107→### B5. MCP (Model Context Protocol) servers are the new "REST API"
   108→
   109→- `modelcontextprotocol/servers` is the canonical repo. 9 official SDKs across languages (C#, Go, Java, Kotlin, PHP, Python, Ruby, Rust, Swift, TypeScript).
   110→- 7 reference servers: `Everything`, `Fetch`, `Filesystem`, `Git`, `Memory`, `Sequential Thinking`, `Time`. The `Memory` reference server is a **knowledge-graph-based persistent memory system** — direct overlap with Context-M's value prop.
   111→- MCP Registry: https://registry.modelcontextprotocol.io/ — discoverable, browseable.
   112→- **GitMCP** turns any GitHub repo into a remote MCP endpoint. Mentioned in 2025-09 GitHub community discussion: "GitHub MCP Server provides an excellent starting point, offering out-of-the-box integration with GitHub repositories, issues, and pull requests."

   142→### B10. Anti-fork-lamprey warning blocks
   143→

   147→### B11. Honesty-coded benchmark blocks (Ponytail pattern)
   148→
   149→- Ponytail's hero shows the benchmark numbers + a methodology footnote in the same line:
   150→  ```
   151→  ~54% less code (up to 94%) · ~20% cheaper · ~27% faster · 100% safe
   152→  Measured on real Claude Code sessions editing a real open-source repo (FastAPI + React),
   153→  against the same agent with no skill. ~54% is the mean across 12 feature tasks
   154→  (Haiku 4.5, n=4); it reaches 94% where an agent over-builds (a date picker) and is
   155→  near zero where the code is already minimal. Full writeup · reproduce it.
   156→  ```
   157→- Plus a benchmark table with **control arms** (caveman, yagni-oneliner, no-skill baseline) — not just "us vs nothing".
   158→- This pattern (numbers + methodology + reproducible link + named control arms) is the **2026 honesty contract** with readers. v1 playbook noted "Mem0 leads README with a benchmark table at top" — but v1 did not capture the **methodology footnote + control arms** discipline.

   160→### B12. Single-binary CLI with self-update (uv pattern)
   161→
   162→- uv's pattern: install via curl OR pip OR pipx, then `uv self update`. The CLI is a single Rust binary. The PyPI package is a thin wrapper.
   163→- Naming convention: **the binary name is `uv`, not `astral-uv` or `astral_uv`**. Match repo name, drop org prefix.
   164→- This pattern correlates strongly with star growth because the install command becomes memorable: `curl -LsSf https://astral.sh/uv/install.sh | sh` is 5 tokens; `pip install astral-uv` is 3 tokens but loses the brand.

   173→### B14. "Visual companion telemetry" transparency
   174→
   175→- obra/superpowers ships a README section literally titled **"Visual companion telemetry"** that transparently discloses what telemetry is collected and why. This replaces the 2018 "we collect anonymous usage data" bury-it-in-paragraph-47 pattern.

   177→### B15. Mixed sentiment on Conventional Commits + Keep a Changelog
   178→
   179→- Keep a Changelog 2.0.0 (Jun 2026) explicitly calls Conventional Commits an antipattern that "adds cognitive overhead by injecting itself into the middle of a workflow". Conventional Changelog maintainers disagree.
   180→- Adoption is real but contested: many top repos still ship hand-written CHANGELOG.md (kubernetes, langchain). Only ~40% of top-100 repos actually use Conventional Commits. Recommendation: use **Conventional Commits for the commit history** but generate the **CHANGELOG.md** with semantic-release or release-please, then hand-edit it before release — the auto-generated form is unreadable.

   186→### C1. OpenClaw: 9k → 302k stars in ~5 months (Nov 2025 → Apr 2026)

   189→- **Tactic 2**: Multi-channel distribution beyond GitHub: a website (openclaw.ai), docs subdomain, Discord, npm package, GitHub App.
   190→- **Tactic 3**: Cross-platform install oneliner (`curl -fsSL https://openclaw.ai/install.sh | bash`).
   191→- **Tactic 4**: Listed itself on the **OpenClaw VPS hosting** partner page (openclawvps.io) for "OpenClaw Statistics 2026" cross-promotion — third-party marketing.

   194→### C2. Ponytail: ~10k → 114k in 6 months (Feb 2026 → Aug 2026)

   201→- **Tactic 6**: Subtle "Works with 20 agents" badge: `https://img.shields.io/badge/works%20with-20%20agents-111111`. Black-on-black style, no logos. Tells the reader "this is portable across your whole stack".

   390→## E. PR-Gate "Accepted-Label" Workflow — Exact YAML / Repo-Settings Pattern (Mem0)
   391→
   392→Mem0's workflow is at `.github/workflows/pr-gate.yml`. The file is 220 lines of YAML. The exact pattern (paraphrased / condensed, copy-paste-safe for any repo):
   393→
   394→```yaml
   395→name: PR Gate
   396→
   397→on:
   398→  pull_request_target:
   399→    types: [opened, reopened, ready_for_review, edited]
   400→  issues:
   401→    types: [labeled]
   402→
   403→concurrency:
   404→  group: pr-gate-${{ github.event_name }}-${{ github.event.action }}-${{ github.event.pull_request.number || github.event.issue.number }}
   405→  cancel-in-progress: ${{ github.event_name == 'pull_request_target' }}
   406→
   407→env:
   408→  GATE_EFFECTIVE_FROM: '2026-08-12T00:00:00Z'   # grandfather clause — PRs opened before this are skipped
   409→
   410→permissions:
   411→  contents: read
   412→  pull-requests: write
   413→  issues: read
   414→
   415→jobs:
   416→  gate:
   417→    # Skip: edited PRs, drafts, bots, same-repo PRs (branch pushes), OWNER/MEMBER/COLLABORATOR authors
   418→    if: >-
   419→      github.event_name == 'pull_request_target' &&
   420→      github.event.action != 'edited' &&
   421→      github.event.pull_request.draft == false &&
   422→      github.event.pull_request.user.type != 'Bot' &&
   423→      github.event.pull_request.head.repo.full_name != github.repository &&
   424→      !contains(fromJSON('["OWNER","MEMBER","COLLABORATOR"]'), github.event.pull_request.author_association)
   425→    runs-on: ubuntu-latest
   426→    steps:
   427→      - uses: actions/github-script@v7
   428→        with:
   429→          script: |
   430→            const pr = context.payload.pull_request;
   431→            const { owner, repo } = context.repo;
   432→
   433→            // 1. Grandfather clause
   434→            const effectiveFrom = process.env.GATE_EFFECTIVE_FROM;
   435→            if (effectiveFrom && Date.parse(pr.created_at) < Date.parse(effectiveFrom)) {
   436→              core.info(`Opened ${pr.created_at}, before the gate took effect ${effectiveFrom}. Skipped.`);
   437→              return;
   438→            }
   439→
   440→            // 2. Skip if already closed
   441→            const { data: current } = await github.rest.pulls.get({ owner, repo, pull_number: pr.number });
   442→            if (current.state !== 'open') { core.info(`#${pr.number} is already ${current.state}. Skipped.`); return; }
   443→
   444→            // 3. Skip docs-only PRs
   445→            const files = await github.paginate(github.rest.pulls.listFiles,
   446→              { owner, repo, pull_number: pr.number, per_page: 100 });
   447→            const rootDocs = new Set(['README.md','CONTRIBUTING.md','CODE_OF_CONDUCT.md','SECURITY.md']);
   448→            const isDocs = (f) => f.startsWith('docs/') || rootDocs.has(f);
   449→            if (files.length > 0 && files.every((file) => isDocs(file.filename))) {
   450→              core.info('Docs-only PR, gate skipped'); return;
   451→            }
   452→
   453→            // 4. Use GraphQL to find linked closing issues + their labels
   454→            const { repository } = await github.graphql(
   455→              `query ($owner: String!, $repo: String!, $number: Int!) {
   456→                repository(owner: $owner, name: $repo) {
   457→                  pullRequest(number: $number) {
   458→                    closingIssuesReferences(first: 20) {
   459→                      nodes { number labels(first: 50) { nodes { name } } }
   460→                    }
   461→                  }
   462→                }
   463→              }`,
   464→              { owner, repo, number: pr.number }
   465→            );
   466→
   467→            const accepted = repository.pullRequest.closingIssuesReferences.nodes
   468→              .filter((issue) => issue.labels.nodes.some((label) => label.name === 'accepted'))
   469→              .map((issue) => issue.number);
   470→
   471→            // 5. If any linked issue has `accepted`, pass
   472→            if (accepted.length > 0) { core.info(`Accepted issue linked: #${accepted.join(', #')}`); return; }
   473→
   474→            // 6. Otherwise post marker comment + close
   475→            const body = [
   476→              '<!-- pr-gate -->',
   477→              'Thanks for taking the time to open this.',
   478→              '',
   479→              'We only review pull requests that fix an issue we have already agreed to take on, so this one is closed for now.',
   480→              '**Closed does not mean rejected.** It means it is not in the queue yet, and reopening takes about a minute.',
   481→              '',
   482→              'To get it reviewed:',
   483→              '1. Make sure an issue describes the problem, with the version you are on, a runnable reproduction, and the real output or traceback you saw.',
   484→              '2. Link it from this pull request description with `Closes #<number>`.',
   485→              '3. Ask a maintainer to label that issue `accepted`. This pull request reopens by itself when they do.',
   486→              '',
   487→              'Issue already labeled `accepted`? Just add `Closes #<number>` to the description. That reopens this too.',
   488→              '',
   489→              'Documentation-only changes skip this gate entirely.',
   490→              '',
   491→              'See [CONTRIBUTING.md](../CONTRIBUTING.md) for the full policy.'
   492→            ].join('\n');
   493→
   494→            await github.rest.issues.createComment({ owner, repo, issue_number: pr.number, body });
   495→            await github.rest.pulls.update({ owner, repo, pull_number: pr.number, state: 'closed' });
   496→            core.info(`Closed #${pr.number}: no accepted issue linked`);
   497→
   498→  reopen:
   499→    # Triggers when `accepted` label is added to an issue, OR when a closed PR is edited (e.g. author adds `Closes #n`)
   500→    if: >-
   501→      (github.event_name == 'issues' && github.event.label.name == 'accepted') ||
   502→      (github.event.action == 'edited' && github.event.pull_request.state == 'closed')
   503→    runs-on: ubuntu-latest
   504→    steps:
   505→      - uses: actions/github-script@v7
   506→        with:
   507→          script: |
   508→            const { owner, repo } = context.repo;
   509→            const marker = '<!-- pr-gate -->';
   510→
   511→            // Read denounced list from .github/VOUCHED.td
   512→            const denounced = await (async () => {
   513→              try {
   514→                const { data } = await github.rest.repos.getContent({
   515→                  owner, repo, path: '.github/VOUCHED.td',
   516→                  ref: context.payload.repository.default_branch
   517→                });
   518→                return new Set(Buffer.from(data.content, 'base64').toString('utf8')
   519→                  .split('\n')
   520→                  .map((line) => line.trim())
   521→                  .filter((line) => line.startsWith('-'))
   522→                  .map((line) => line.slice(1).split(/\s+/)[0].split(':').pop().toLowerCase())
   523→                  .filter(Boolean));
   524→              } catch (error) {
   525→                core.warning(`Could not read VOUCHED.td, treating nobody as denounced: ${error.message}`);
   526→                return new Set();
   527→              }
   528→            })();
   529→
   530→            const isReopenable = async (number) => {
   531→              const { repository } = await github.graphql(
   532→                `query ($owner: String!, $repo: String!, $number: Int!) {
   533→                  repository(owner: $owner, name: $repo) {
   534→                    pullRequest(number: $number) {
   535→                      state
   536→                      author { login }
   537→                      closingIssuesReferences(first: 20) {
   538→                        nodes { labels(first: 50) { nodes { name } } }
   539→                      }
   540→                    }
   541→                  }
   542→                }`,
   543→                { owner, repo, number }
   544→              );
   545→              const pr = repository.pullRequest;
   546→              if (denounced.has(pr.author?.login?.toLowerCase())) {
   547→                core.info(`#${number} is from a denounced author. Vouch outranks this gate.`);
   548→                return false;
   549→              }
   550→              return pr.state === 'CLOSED' &&
   551→                pr.closingIssuesReferences.nodes.some((issue) =>
   552→                  issue.labels.nodes.some((label) => label.name === 'accepted'));
   553→            };
   554→
   555→            let candidates;
   556→            if (context.eventName === 'issues') {
   557→              const { repository } = await github.graphql(
   558→                `query ($owner: String!, $repo: String!, $number: Int!) {
   559→                  repository(owner: $owner, name: $repo) {
   560→                    issue(number: $number) {
   561→                      closedByPullRequestsReferences(first: 20, includeClosedPrs: true) {
   562→                        nodes { number }
   563→                      }
   564→                    }
   565→                  }
   566→                }`,
   567→                { owner, repo, number: context.payload.issue.number }
   568→              );
   569→              candidates = repository.issue.closedByPullRequestsReferences.nodes.map((pr) => pr.number);
   570→            } else {
   571→              candidates = [context.payload.pull_request.number];
   572→            }
   573→
   574→            for (const number of candidates) {
   575→              if (!(await isReopenable(number))) { core.info(`#${number} not reopenable. Skipped.`); continue; }
   576→              const comments = await github.paginate(github.rest.issues.listComments,
   577→                { owner, repo, issue_number: number, per_page: 100 });
   578→              if (!comments.some((comment) => comment.body?.startsWith(marker))) {
   579→                core.info(`#${number} was not closed by this gate. Left alone.`); continue;
   580→              }
   581→              try { await github.rest.pulls.update({ owner, repo, pull_number: number, state: 'open' }); }
   582→              catch (error) { core.warning(`Could not reopen #${number}: ${error.message}`); continue; }
   583→              await github.rest.issues.createComment({
   584→                owner, repo, issue_number: number,
   585→                body: 'An `accepted` issue is linked now, so this is open again and ready for review.'
   586→              });
   587→              core.info(`Reopened #${number}`);
   588→            }
   589→```
   590→
   591→### E1. Required repo settings to make the gate actually work
   592→
   593→1. **Branch protection on `main`**: require `pull_request_target`-driven status checks; do not allow direct pushes; require PR approval.
   594→2. **Settings → Actions → General → Workflow permissions**: read + write (the workflow needs to write PR state and comments).
   595→3. **Settings → Actions → General → Fork pull request workflows**: "Run workflows from the pull_request_target event" must be enabled (this is the default for public repos).
   596→4. **Settings → Issues → Labels**: create the `accepted` label (any color). The workflow doesn't create it for you.
   597→5. **Settings → General → Features → Issues**: keep Issues enabled (the workflow uses GraphQL `closingIssuesReferences` which requires Issues).
   598→6. **`.github/VOUCHED.td`** file (optional): plain text, one handle per line, alphabetically sorted, optional `platform:username` (e.g. `github:mitchellh`). Prefix with `-` for denounced. Empty file is fine. See Mem0's 427-line VOUCHED.td as a reference.
   599→7. **CONTRIBUTING.md must reference the gate** so users aren't surprised (see Mem0's "PR Gate" section).
   600→
   601→### E2. Why this design works
   602→
   603→- **Two-jobs split** means the gate fires on PR-open events (closes wrong PRs immediately) and the reopen job fires on `issues: labeled` (auto-reopens the moment a maintainer labels the linked issue `accepted`). The PR author doesn't have to do anything after the issue is accepted.
   604→- **`<!-- pr-gate -->` marker comment** is what the reopen job searches for — so it never reopens a PR that was closed manually by a human for other reasons.
   605→- **Docs-only skip**: PRs touching only `README.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, or anything under `docs/` bypass the gate. Docs contributors are not blocked.
   606→- **Grandfather clause** (`GATE_EFFECTIVE_FROM`): PRs opened before the gate went live are skipped, so you don't retroactively close a backlog of valid PRs.
   607→- **Bot + same-repo + OWNER/MEMBER/COLLABORATOR skips**: depedency-bot PRs, branch pushes by maintainers, and org members don't hit the gate.
   608→- **Closed does not mean rejected**: the comment wording is doing real psychological work — it tells the contributor the gate is a queue, not a rejection.
