   442→- Bench variance root-cause analysis (the 43-49% drift on
   443→  +unmess+dissim across identical runs):
   444→  * Source 1: PYTHONHASHSEED randomizes set/dict iteration order per
   445→    Python process. The palace._flat_search() comment says it iterates
   446→    candidate_ids in palace row order to avoid this, but the SLB cache
   447→    lookup uses np.argmax over sims — if cosine similarities are very
   448→    close (which they are for templated near-duplicate queries like
   449→    "What is the name of beam_1?" / "What is the age of beam_1?"), BLAS
   450→    ULP drift across processes can flip which cached entry is "best",
   451→    flipping the threshold comparison (cosine ~0.97 ≈ SLB threshold).
   452→  * Source 2: OpenBLAS uses non-deterministic summation order for
   453→    matmul, so `qv @ centroid` differs at the ULP level across runs,
   454→    and `np.argsort(-sc)` breaks the ULP-level ties differently.
